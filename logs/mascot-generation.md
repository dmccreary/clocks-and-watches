## 1. Finding the "Mascot Generator"

The first prompt, "run the mascot generator," didn't name a script. There is
no standalone generator in the repo. The `book-installer` skill routes the
keyword "mascot" to its `learning-mascot.md` guide, which is a workflow: a
design Q&A, then file generation, then image prompts for the user to run in
an image tool, then trimming and testing. That guide was treated as the
generator.

## 3. Designing Chrono

The guide asks for the design questions all at once, with suggested
defaults. The context was a high school course on building clocks with
MicroPython, with the book's theme colors purple `#642580` and teal
`#41BAC1`.

| Question | Options offered | User's choice |
|---|---|---|
| Character | round-face robot, cuckoo bird, owl with a wristwatch, octopus tinkerer | **Round-face robot** |
| Name (gender-neutral) | Tick, Chrono, Quartz, Sprocket | **Chrono** |
| Catchphrase | "Let's make time tick!", "Every second counts!", "Time to build!", "Let's debug this!" | **"Let's make time tick!"** |
| Art style | flat vector cartoon, soft 3D, hand-drawn sketch, pixel art | **Flat vector cartoon** |

Defaults the user didn't override: the book's purple and teal, and a
curious, patient, playful, encouraging personality.

**The design idea:** Chrono's head *is* a round smartwatch display, like the
GC9A01 and GC9B72 screens the kits build toward. It has a thin bezel and a
silver watch crown. Chrono's face is drawn on the screen in glowing teal, so
each pose changes the eyes and mouth rather than the body. That gives seven
poses one consistent body, which image generators find much easier to repeat.

**One detail that mattered for the renderer:** `render-mascot-guide.py` fills
`{{SUBJECT}}` into lines like "Use {{SUBJECT}}-flavored metaphors." The
Subject field was written as "timekeeping (building clocks and watches with
MicroPython on the Raspberry Pi Pico)". The renderer strips a trailing
parenthetical, so the rules read "timekeeping-flavored metaphors" while the
character sheet keeps the full description. The same trick keeps the Species
field reading plainly as "Robot".

## 5. Trimming and Testing the Images

The user generated the seven poses and saved them into `docs/img/mascot/`.
Before changing anything, a quick Pillow check confirmed that all seven were
RGBA with fully transparent corners, but carried 22–240 px of empty padding.
The trim script overwrites files in place, so the originals were first
copied to the session scratchpad.

The trim script lives at `../ibook-skills/src/image-utils/trim-padding-from-image.py`.
`$BK_HOME` was not set in this shell, so the guide's `$BK_HOME/...` path
didn't resolve. The script crops each image to its visible content plus a
4 px border.

The test page runs the same checks in the browser. All seven passed on the
first try.

## 6. A CSS Bug: the 90 px Box Only Limited Width

On the test page, every mascot was 90 px wide but 93–210 px tall. Chrono is a
tall figure, so the admonitions stretched, and the thinking pose made a box
more than twice the intended height.

**Cause:** the guide's CSS selector `.mascot-admonition-img` sets
`height: var(--mascot-size)`. But MkDocs Material has
`.md-typeset img { height: auto }`, which is more specific (0,1,1 against
0,1,0), so the height was ignored.

**Fix:** the selector is now `.md-typeset img.mascot-admonition-img`, with a
comment explaining why. All seven poses now fit a 90 × 90 box, and
`object-fit: contain` keeps their proportions.

This bug lives in the skill's template, so every book with a tall mascot has
it. A separate task was suggested to fix it in the ibook-skills repo, and the
user started it in another session.

## 7. Preview-Server Gotchas

- **The server didn't pick up edits.** `.claude/launch.json` runs
  `mkdocs serve ... --no-livereload`. With that flag, the server did not
  rebuild when files changed. After the CSS fix, the page still reported
  the old sizes, and fetching `mascot.css` showed the old rule. Restarting
  the server fixed it, and it was restarted after every later round of edits.
- **Blank screenshots.** A screenshot taken in the same batch right after
  `scrollIntoView` often came back blank white. A separate screenshot call
  worked every time.

## 8. The Backslash Fix

The lab 00 note had the title `"Why \"LED\" and not a number?"`, and the
backslashes showed up on the page. They were removed, leaving plain quotes
inside the quoted title.

That can confuse some parsers, so the rendered page was checked. The
admonition regular expression in Python-Markdown matches up to the *last*
quote on the line, so the title renders as **Why "LED" and not a number?**,
and the box's body text is intact.

## 9. Placing Chrono in the Labs

The request "update the labs" arrived while the image testing was still
running. Read in context, it meant placing Chrono in the kit's pages. The
chapter-updater guide requires reading every page and proposing a plan
before editing. The plan was proposed after all 14 pages were read, but the

### The rules that shaped the plan

The rules come from `mascot-placement-rules.md` (rendered into the content
guide), and `validate-chapter-mascots.py` enforces the hard limits:

- exactly one welcome, and at most one celebration, per page
- never two mascot boxes in a row without prose between them
- body text of 1–3 sentences (a welcome may run to 4), with no
  decorative boxes
- each pose does one job: welcome sells the lab, thinking marks a big
  idea, tip gives a shortcut, warning names a pitfall *and* its fix,
  encourage supports a hard part, celebration names the exact skill learned
- the first appearance in the book is a one-time self-introduction

Two details of how the validator works shaped the writing:

- It counts a sentence at every `.`, `!`, or `?` followed by a space. One
  draft welcome opened with "No WiFi? No problem." and would have counted 5
  sentences, so it was rewritten before it was placed.
- It recognizes the self-introduction by a numbered list whose items start
  with **bold** text, so Chrono's six jobs are written as `1. **Welcome** ...`.

**Placement pattern:** welcomes go after each lab's opening paragraph, before
"What You Will Learn". Celebrations go just before the **Next:** link (or
**Back to:** on lab 12). Each celebration names the skills from that lab and
points to the next one.

**Switched, not added:** five existing boxes that were already 1–3 sentences
became Chrono boxes with their text unchanged, except for the 3V3 warning.
That one gained a sentence naming the pitfall's cause: VSYS and VBUS, which
carry about 5 volts, sit a few pins from 3V3. The warning rule asks for the
reason behind a pitfall, not just the rule.

**Deliberately left alone:**

- Six longer notes, such as the flash-size trick and the missing
  corners. Switching them would have meant cutting them to 3 sentences
  and losing content.
- All 15 "Try This" and extension tips. They are exercises, and the tip
  pose is for shortcuts.
- The teacher notes, which are instructor-facing and exempt from the
  mascot rules.
- The neutral pose, used on no lab page. The rules keep it for asides
  that fit none of the other six jobs.

**Avoiding repetition:** several draft welcomes repeated the lab's own
opening paragraph. Examples are the microwaves in lab 08, "the big one" in
lab 12, and the uses listed for the timer in lab 11. Each was rewritten to
make a point the page doesn't already make. The claim in lab 11 about
microwaves was softened to "on many models," because not every microwave
adds 30 seconds when you press Start.

## 10. Shrinking the Images

The generated poses were 0.8–1.6 MB each but display at 90 px, and a lab page
shows two to four of them. The guide's target is 200–400 px and about
100 KB.

Resizing the already-trimmed images would have shrunk the 4 px border to
about 1 px. The trim script can't add padding back, so the test page would
have failed. The resize was therefore done from the backed-up originals:

1. Scale each original so that its visible content is 392 px on the longest
   side (392 + 4 + 4 = 400), using Lanczos resampling.
2. Run the trim script, which restores exactly 4 px of border.
3. Re-save with PNG optimization.

| Pose | As generated | After first trim | Final | Final size |
|---|---|---|---|---|
| neutral | 1024 × 1536, 1,450 KB | 788 × 1443 | 222 × 402 | 96 KB |
| welcome | 1145 × 1374, 827 KB | 889 × 1272 | 282 × 401 | 111 KB |
| thinking | 1024 × 1536, 1,381 KB | 626 × 1458 | 175 × 400 | 82 KB |
| tip | 1145 × 1374, 860 KB | 874 × 1274 | 277 × 400 | 114 KB |
| warning | 1024 × 1536, 1,477 KB | 914 × 1399 | 265 × 401 | 111 KB |
| encouraging | 1024 × 1536, 1,536 KB | 880 × 1480 | 242 × 400 | 107 KB |
| celebration | 1222 × 1287, 859 KB | 1064 × 1094 | 389 × 401 | 151 KB |

The test page passed all seven again after the resize. At 90 px, 400 px
source images are still sharp on high-density screens.
